# BharatFresh Backend

## Setup

1. Create a PostgreSQL database.
2. Copy `.env.example` to `.env` and set `DATABASE_URL`.
3. Run migrations.
4. Seed products.
5. Start the API server.

```bash
npm install
npm run migrate
npm run seed
npm run dev
```

If your managed Postgres uses a self-signed or provider-managed certificate chain, keep `DB_SSL_ALLOW_SELF_SIGNED=true` in `.env`.

## Core Decisions

- OTP is mocked in MVP. `POST /api/auth/send-otp` always stores and returns `111111`.
- Auth tokens are HMAC-signed bearer tokens generated by the server.
- Buyer checkout creates market requests, not direct seller orders.
- Seller acceptance creates the actual assignment/order record.
- Maps use stored latitude/longitude and radius matching in PostgreSQL.
- Payment and delivery remain offline in MVP.

## Main Endpoints

- `POST /api/auth/send-otp`
- `POST /api/auth/verify-otp`
- `POST /api/auth/register`
- `GET /api/auth/me`
- `GET|PUT /api/buyer/profile`
- `GET|POST|PUT /api/buyer/addresses`
- `GET|PUT /api/seller/profile`
- `GET|POST|PUT|DELETE /api/seller/inventory`
- `GET /api/seller/requests`
- `POST /api/seller/requests/:id/accept`
- `GET /api/products/search`
- `GET /api/products/nearby`
- `GET /api/sellers/nearby`
- `GET /api/sellers/:id/inventory`
- `GET|POST /api/cart`
- `DELETE /api/cart/items/:id`
- `POST /api/orders/checkout`
- `GET /api/orders/buyer`
- `GET /api/orders/seller`
- `PUT /api/orders/:id/status`
- `GET /api/orders/:id`
- `POST /api/notifications/tokens`
- `GET /api/notifications`
